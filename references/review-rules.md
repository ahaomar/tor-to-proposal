# Review rules — read before showing the user any draft

## The four questions every paragraph must survive

1. **Trace**: does every fact here trace to the ToR (p.X), a user input, or a cited source?
2. **Claim**: did we claim anything the CV does not support? (GAP list is the arbiter.)
3. **Client words**: does this paragraph use the client's own terminology, not our synonyms?
4. **Score**: which evaluation criterion does this paragraph earn points under? If none, it is decoration — cut it.

## Banned superlatives (cover-letter lint enforces this list)

leading, world-class, world leading, renowned, premier, cutting-edge,
state-of-the-art, best-in-class, unparalleled, top-tier, preeminent,
unrivaled, foremost, exceptional expertise, vast experience.

Replace each with evidence: "led 4 country evaluations (p.X requirement; CV §3)".

## Style

- One page cover letter, always.
- Mirror the ToR's section names for the technical response — evaluators score
  against a grid that follows the ToR's own structure.
- Quantify every experience bullet. No number available → [FILL] + ask the user.
- Passive-aggressive hedging ("we hope to potentially...") reads as weakness.
  State facts; cite them; stop.
- Dates, names, reference numbers: copy-paste from the ToR, never retype.

## Pre-submission checklist (audit.mjs covers 1–3 mechanically)

1. [ ] Zero `[FILL]` remaining.
2. [ ] Compliance matrix: every row Complete.
3. [ ] No claim-shaped sentence without a trace.
4. [ ] Cover letter lint PASS.
5. [ ] Simulator at-risk ≈ 0 (or user accepted the residual consciously).
6. [ ] Financial form totals are the CLIENT's formulas (we never overwrite them).
7. [ ] File names per submission instructions (some portals reject wrong names).
8. [ ] Submitted via the ToR's channel only, before the deadline, in the
       timezone the ToR states ("17:00 GMT" is not your local 17:00).
